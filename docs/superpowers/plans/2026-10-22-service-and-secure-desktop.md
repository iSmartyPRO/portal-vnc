# PortalVNC — План №2: служба Windows, значок в трее, экран блокировки/UAC

**Goal:** Агент работает как автозапускаемая служба Windows, по настройке показывает значок в трее, и захватывает/управляет интерактивным рабочим столом, включая экран блокировки и окна UAC (Secure Desktop).

**Architecture (модель «тонкая служба + рабочий в сессии»):**
- **Служба** (`--service`, LocalSystem, session 0) — супервизор: запускает **рабочий** процесс в активной консольной сессии как SYSTEM на `winsta0\default`, следит за ним и перезапускает при смене сессии (вход/выход/переключение пользователя через `SERVICE_CONTROL_SESSIONCHANGE`). Сеть/захват служба сама не делает.
- **Рабочий** (`--worker`, SYSTEM, активная сессия) — это существующий `RfbServer` (сокет, mTLS, рукопожатие, авторизация, RFB, захват, ввод). Поскольку он SYSTEM в пользовательской сессии и **следит за активным рабочим столом** (`OpenInputDesktop`/`SetThreadDesktop`), его GDI-захват и ввод видят обычный рабочий стол, экран блокировки и Secure Desktop (UAC).
- **Значок в трее** показывает рабочий (если `trayIcon=true`): оболочка пользователя в той же сессии его отображает.
- **Dev-режим** (`--config`) без изменений: консольный агент для разработки.

Это снимает необходимость гонять кадры между процессами: вся логика RFB остаётся в одном процессе, служба лишь запускает его в правильной сессии/рабочем столе.

**Tech Stack:** Win32 Service API (SCM), WTS API (активная сессия), `CreateProcessAsUser` + `DuplicateTokenEx`, `OpenInputDesktop`/`SetThreadDesktop`, `Shell_NotifyIcon`.

**Spec:** `docs/superpowers/specs/2026-10-22-portalvnc-design.md`

## Задачи

### Task 1: Следование за активным рабочим столом в захвате/вводе
- `capture_hub` владеет вводом (InputInjector) и очередью ввода; один поток-«рабочий стол» на каждой итерации: привязывается к активному input-desktop (если сменился), применяет ввод, делает захват. Клиентские потоки кладут ввод в очередь хаба.
- Тест: дифф и захват уже покрыты; добавить юнит на очередь ввода (enqueue→drain порядок) без реального SendInput (вынести сериализацию событий в тестируемую функцию).

### Task 2: Служба Windows (SCM)
- `--install` (создаёт службу `PortalVNC`, автозапуск, аккаунт LocalSystem, `SERVICE_INTERACTIVE`? нет — launch worker сами), `--uninstall`, `--service` (ServiceMain + SCM status + остановка).
- Служба запускает рабочего в активной сессии; на `SESSIONCHANGE` перезапускает.
- Ручная проверка: `sc query PortalVNC`, подключение просмотрщика к службе.

### Task 3: Запуск рабочего как SYSTEM в активной сессии
- `WTSGetActiveConsoleSessionId`, `WTSQueryUserToken` или дублирование токена службы с установкой SessionId, `CreateProcessAsUserW` с `lpDesktop="winsta0\\default"`.
- Перезапуск при падении и при смене сессии.

### Task 4: Значок в трее
- `tray.*`: `Shell_NotifyIcon` со стандартной иконкой «сетевой компьютер» (`IDI_*`/shell32), меню «О программе/Статус». Показывается рабочим при `trayIcon=true`.

### Task 5: Экран блокировки/UAC
- Рабочий следит за input-desktop; проверка: заблокировать экран и убедиться, что просмотрщик продолжает видеть изображение (ручная проверка, нужен реальный вход).

## Что оставлено строителю
- Точный способ получить SYSTEM-токен для нужной сессии (дублирование токена службы vs `WTSQueryUserToken`+повышение).
- Поведение, когда активной консольной сессии нет (только RDP-сессии) — к Плану №3 (мультисессии).
